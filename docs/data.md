# 원본 데이터 확인 기록

## 따릉이 대여이력 (2023-01 ~ 2026-06)

확인일 2026-09-16. `work/`의 확인 스크립트로 `data/bronze/trips` 전체(42개월)를 DuckDB로 조회함.

### 파일 형식
- 서울 열린데이터광장 OA-15182. 2023~2025년은 연도별 ZIP 안에 월별 CSV 12개, 2026년은 월별 CSV
- 인코딩 cp949, 모든 값을 따옴표로 감쌈, 빈 값은 `\N`
- 컬럼: 2023~2025년은 17개, 2026년 파일에는 마지막 `자전거구분`이 없어 16개
- 대여소번호는 앞자리 0이 있는 문자열(`"01653"`), 대여소ID는 `ST-1121` 형식
- 원본 CSV 약 24GB → 문자열 Parquet(zstd) 2.8GB, 변환 약 8분

### 확인한 품질
| 항목 | 결과 | 처리 방향 |
|---|---|---|
| 대여·반납 시각 형식 오류 | 0건 | - |
| 파일의 달과 대여 시각의 달이 다른 행 | 0건 | - |
| 대여소ID ↔ 대여소번호 | 1:1 (한쪽에 여럿 대응 0건) | 대여소 키는 ID 사용 |
| 반납대여소 정보(번호·이름·거치대·ID)가 모두 빈 행 | 666,844건 (0.46%), 달마다 1~2만 건 | 대여 수 집계에는 포함(대여는 일어남), 반납 집계에서는 제외 |
| 완전히 같은 행 (자전거, 대여 시각·대여소, 반납 시각·대여소) | 10,252건 | 하나만 남김 |
| 이용시간 0분 | 543,275건 (0.38%). 이 중 같은 대여소 반납 442,814건, 그중 거리도 0인 것 366,156건 | 아래 참고 |
| 반납 시각이 대여 시각보다 이른 행 | 1건 (1초 차이, 이용시간 0분) | 이용시간 0분 규칙으로 함께 처리 |
| 이용자종류 | 내국인 99.0%, 비회원 0.8%, 외국인 0.2% | 모두 포함 |

**이용시간 0분 + 같은 대여소 반납(442,814건)**: 빌린 자리에서 1분 안에 돌려준 경우라 실제 이동이 아니라 대여 취소·고장 교환일 가능성이 큼. 대여소의 자전거가 실제로 줄지 않으므로 수요 집계에서 뺀다. 다른 대여소에 0분으로 반납한 99,823건은 이동이 있었던 것으로 보고 남긴다. 반납 대여소가 빈 0분 기록(638건)도 대여로 센다. 중복 제거 뒤 dbt `stg_trips` 기준으로는 취소 442,781건, 남은 대여 144,188,660건.

### 시간대별 대여 비율 (전체 기간)
출퇴근 두 봉우리: 8시 7.5%, 18시 9.8%(최대). 새벽 4시 0.6%(최소).

### 해석할 때 주의
대여 기록은 **실제 수요가 아니라 "자전거가 있어서 빌릴 수 있었던" 수요**다. 대여소가 비어 있던 시간의 수요는 기록되지 않는다(중도절단). 부족이 잦은 대여소일수록 예측이 실제 수요보다 낮게 나올 수 있다.

## 기상청 ASOS 시간자료 (서울 108, 2023-01 ~ 2026-06)
- 30,648시간 모두 받음(빠진 시간 0). 공공데이터포털 AsosHourlyInfoService
- **강수(rn)**: 4~10월은 매시 직전 1시간 누적. **11~3월은 0·3·6…시에만 직전 3시간 누적**이 보고되고 다른 시각은 빈 값이다. 비가 안 온 시간도 빈 값이다
- **눈**: `dsnw`는 쌓인 눈 깊이(눈이 그친 뒤에도 남음), `hr3Fhsc`는 3시간 신적설(3시간 간격 보고)
- dbt `stg_weather_hourly`는 관측 시각 t의 값을 대여 시간 t−1시간에 붙이고, 겨울 3시간 누적 강수는 앞선 세 시간에 1/3씩 나누며, 3시간 신적설 > 0이면 그 세 시간을 "새로 눈이 옴"으로 둔다
